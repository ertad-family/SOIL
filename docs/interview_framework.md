# SOIL: Organizational Functions Matrix

## Overview

This document defines the conditional logic for the founder interview form. Functions are displayed based on:
1. **Organization Type** (primary axis)
2. **Lifecycle Stage** (secondary axis)

### Legend

| Symbol | Meaning |
|--------|---------|
| ● | Active — expected for this type/stage, shown by default |
| ○ | Dimmed — not typical, but can be activated by user |
| — | Hidden — irrelevant for this organization type |

### Lifecycle Stages

| Stage | Characteristics |
|-------|-----------------|
| **Formation** | Registered, operations started, <10 people |
| **Establishment** | Stable operations, growing team, 10-30 people |
| **Growth** | Scaling, formalizing processes, 30-100 people |
| **Maturity** | Established structure, 100+ people |

## Function Customization Logic

### Adding Functions from Catalog

Users can browse and add functions from other organization types. This addresses cases where an organization has non-typical functions for its type.

**UX Flow:**
1. User clicks "+ Add Function"
2. Selects "From catalog"
3. Browses functions by organization type
4. Selects function to add
5. Function appears as active (●)

**Data capture:** When user adds cross-type function, capture:
- Source type (where function came from)
- Reason (optional): "Why did you have this function?"

### Adding Custom Functions

Users can create entirely new functions not in any catalog.

**UX Flow:**
1. User clicks "+ Add Function"
2. Selects "Custom function"
3. Enters:
   - Function name (required)
   - Parent category (select existing or create new)
   - Description (optional)
4. Function appears as active (●)

**Data capture:**
- Custom function name
- Parent category
- Description
- All standard metrics (headcount, FTE%, frequency, etc.)

**Research value:** Custom functions are valuable signals for:
- Emerging organizational patterns
- Industry-specific innovations
- Hybrid business model indicators
- Evolution of organizational structures

## Wizard 3: Dynamic Picture (Peak → Death)

### Purpose

Capture the degradation story from peak operations to closure through:
1. Pattern-based targeted questions (from Health Check data)
2. Founder-driven event timeline

### Step 1: Pattern Aggregation

System analyzes Health Check data from Wizard 1 and detects cross-functional patterns:

| Pattern | Trigger |
|---------|---------|
| **Systemic Turnover** | High turnover in 2+ functions |
| **Widespread Understaffing** | Understaffed in 2+ functions |
| **Budget Squeeze** | Severe/Some pressure in 2+ functions |
| **Quality Erosion** | Serious/Some issues in 2+ functions |
| **Leadership Crisis** | Vacuum/Gaps in 2+ functions |
| **Internal Friction** | Cross-function conflict in 2+ pairs |
| **Concentrated Failure** | One function with 3+ problems |
| **Cascade Signature** | Understaffing + Quality issues in same function |

### Step 2: Targeted Questions by Pattern

**Systemic Turnover:**
- When did turnover become noticeable?
- What did you attribute it to at the time?
- How do you understand it now?
- Did you try to change anything?

**Widespread Understaffing:**
- Was this a conscious decision (cost saving) or inability to hire?
- When did the shortage become critical?
- Which function suffered first?

**Budget Squeeze:**
- When did constraints begin?
- What was cut first?
- How did the team react?

**Quality Erosion:**
- When did you notice quality declining?
- Do you connect it with other problems (staffing, budget)?
- How did customers react?

**Leadership Crisis:**
- Why did gaps emerge?
- Did you try to fill them? What got in the way?
- How did teams cope without leadership?

**Internal Friction:**
- Which functions had the main conflict?
- What was the dispute about (resources, priorities, quality, responsibility)?
- How did you try to resolve it?

**Concentrated Failure:**
- Function [X] shows multiple problems. Was this the epicenter of crisis?
- Did problems arise simultaneously or sequentially?

**Cascade Signature:**
- Did understaffing lead to quality issues, or vice versa?
- Which came first?

## Wizard 6: Narrative

### Purpose

Capture meaning, interpretation, lessons, and closure in the founder's own words. This is where structured data becomes human wisdom.

### Format Options

| Option | When to use |
|--------|-------------|
| **Text responses** | Self-service track, async |
| **AI interview** | Guided conversation, async |
| **Human interview** | Premium track, with Pathologist |

### Intro Screen

> "This is the last step. Here, we step back from the data and ask: what does it all mean? There are no right answers. Just your truth."

### Core Questions

**Understanding what happened:**
> "Looking at everything — your organization, the environment, your own journey..."

1. What do you believe was the primary cause of death?
2. Was there a point of no return? When?
3. Could it have been prevented? What would it have taken?

**Hindsight:**
> "With the clarity that only comes after..."

4. What would you do differently if you could go back?
5. What would you do exactly the same?
6. What did you not see that you wish you had?

**Lessons:**
> "Every ending teaches something..."

7. What did you learn about building organizations?
8. What did you learn about yourself?
9. What surprised you most about the whole experience?

**Advice:**
> "If someone was standing where you stood at the beginning..."

10. What would you tell them?
11. What question should they ask themselves that you didn't?

**Legacy:**
> "Before we close..."

12. What are you most proud of about [Organization Name]?
13. What do you want people to remember about it?
14. Is there anything else you want to say — to your team, your customers, yourself?

### AI Interview Mode

If founder chooses AI interview:
- Conversational flow based on core questions
- Follow-up questions based on responses
- Ability to go deeper on specific threads
- Summary generated at end for founder review

### Human Interview Mode (Pathologist)

If founder chooses human interview:
- Pathologist has access to all previous wizard data
- Core questions as guide, not script
- 45-60 minute session
- Recording transcribed and summarized
- Founder reviews and approves final narrative

### Therapeutic Elements

**Question-level support:**
- After difficult questions: "Take your time. There's no rush."
- After emotional responses detected: "Thank you for sharing that. It matters."

**Completion:**
> "You've done something important here. Not just for the data — for yourself. [Organization Name] is now part of the record. Your experience will help others. And maybe, in telling this story, you've found a little more peace with it."

## Therapeutic Design

### Core Positioning

Not "help science, tell us about your failure" but **"go through a structured closure process and restore pride in what you built."**

### Language Principles

| Avoid | Use Instead |
|-------|-------------|
| What went wrong? | What did you learn? |
| Failed function | Function that needed more support |
| Death | Closure |
| Failure | End of chapter |
| Problems | Challenges |
| Mistakes | Decisions with incomplete information |

### Contextual Affirmations

Triggered by specific data patterns:

| Trigger | Affirmation |
|---------|-------------|
| Low satisfaction on function | "Most founders struggle with [X]. You're not alone." |
| Many functions without dedicated owner | "Running multiple functions yourself is exhausting. You carried a lot." |
| Early stage death (Formation) | "Building something from nothing is already an achievement few attempt." |
| High headcount at peak | "You created jobs. Real people's lives were better because you built this." |
| Outsourced + low satisfaction | "Finding the right partners is one of the hardest parts. Everyone gets burned." |
| Function stopped mid-life | "Knowing when to cut something takes courage." |
| Long lifespan (years) | "Keeping something alive for [X] years is remarkable. Most never get there." |
| Multiple co-founders | "You convinced others to believe in your vision. That's leadership." |
| Pivot detected in timeline | "Adapting to reality is not failure — it's wisdom." |
| High formalization level | "You built real systems. That's more than most ever achieve." |
| Founder as owner of many functions | "You wore many hats. That's the startup reality, and you handled it." |

### Wizard Completion Summaries

Each wizard ends with personalized summary + affirmation:

**After Functional Mapping:**
> "You've mapped [N] functions. Your organization had real structure — [top 3 functions by FTE] working together. That's not nothing. That's a company you built."

**After Dynamic Picture:**
> "From [founding] to [peak] to [closure] — that's a complete arc. Every chapter had meaning, even the hard ones."

**After Environment Analysis:**
> "You operated in [market conditions]. Many factors were outside your control. Recognizing that is important."

**After Narrative:**
> "Your story is now preserved. What you learned will help others. That's a legacy."

### Micro-Celebrations

Small positive feedback throughout:

- Completing a section: "Great progress. [X] more to go."
- Filling difficult questions: "Thank you for your honesty. This takes courage."
- Returning after pause: "Welcome back. Ready when you are."
- 50% complete: "Halfway there. You're doing important work."

### Closure Ritual (End of Process)

Final screen with:
1. Visual preview of cenotaph
2. Summary stats (lifespan, team size at peak, functions mapped)
3. Personalized message based on collected data
4. Option to share or keep private
5. Invitation to community

> "Every venture that closes makes room for what comes next — for you, and for everyone who learns from your experience. Thank you for honoring [Organization Name] with this memorial."

## Implementation Notes

### Activation Trigger

When user activates a dimmed (○) function, optionally prompt:
> "This function is not typical for [org type] at [stage]. What led you to implement it?"

This captures valuable context about organizational innovation or necessity.

### Early Termination Functions

Track functions that were active but stopped before organization death:
- When stopped (date/stage)
- Why stopped (optional)

This reveals function lifecycle patterns within organizations.

### Function Dependencies

Some functions logically depend on others. Consider soft warnings:
- Sales Operations without Pipeline Management
- DevOps without Development
- Retention without Support

Not blocking, but prompts for confirmation.
